# ac-esp（学习版）

被注入进 **AssaultCube**（32 位 OpenGL 游戏）的 ESP 外挂，简化重写版：
读游戏内存 → 世界坐标投影成屏幕坐标 → 用 imgui 的 draw list 画方框 / 引导线 / 血条。

代码里所有注释都是"为什么这么写"，而不是"这行在干嘛"，方便照着学。

---

## 一、从哪个文件开始读（推荐顺序）

| 顺序 | 文件 | 一句话作用 | 关键知识点 |
| --- | --- | --- | --- |
| 1 | `src/offset.rs` | 偏移表：数据在内存里的位置 | 偏移 = 绝对地址 − 模块基址；为什么用 `Option` 表示未验证 |
| 2 | `src/memory.rs` | 地基：安全读内存 + 世界转屏幕 | `VirtualQuery` 防崩、`read_unaligned`、透视除法 |
| 3 | `src/data.rs` | 数据线程：读内存 → 快照 | `Arc<RwLock<>>`、合理性校验、为什么单独开线程 |
| 4 | `src/esp.rs` | 把快照画成方框 | foreground draw list、`build()` 链式构造器、热循环性能 |
| 5 | `src/config.rs` | 所有开关和参数 | 枚举 ↔ 下拉框的 index 惯例 |
| 6 | `src/menu.rs` | imgui 菜单 | `ui.window(...).build(\|\| ...)`、控件返回值 |
| 7 | `src/hotkeys.rs` | 热键 + "吞键"窗口过程 | 边沿检测、`SetWindowLongPtrW` 包一层 wndproc |
| 8 | `src/fonts.rs` | 中文字体 | 为什么中文会变「?」、`glyph_ranges` |
| 9 | `src/aimbot.rs` | 自瞄：选目标 + 移鼠标 | `SendInput` 相对移动、小数余量、hold 模式 |
| 10 | `src/lib.rs` | 入口，把上面全部串起来 | `DllMain`、hudhook 回调顺序、输入过滤 |

> 如果只想快速理解"ESP 到底怎么画出来的"：**`memory.rs` 的 `world_to_screen` + `esp.rs` 的 `draw`**
> 这两个函数就是全部核心，其他都是给它们服务的。

## 二、运行流程

```
游戏加载 dll
  └─ DllMain(DLL_PROCESS_ATTACH)          <- lib.rs
       └─ 新线程 → run()
            ├─ memory::module_base()      拿游戏基址
            ├─ data::spawn()              数据线程：每 2ms 读一次内存
            └─ hudhook 挂钩 wglSwapBuffers
                 └─ 每帧 render()
                      ├─ 处理热键
                      ├─ esp::draw()      画方框/线/血条
                      └─ menu::draw()     画菜单
```

三条铁律：

1. **渲染回调跑在游戏线程上**，里面只画图，读内存交给数据线程。
2. **读内存前必须查可读性**，野指针会让游戏直接崩。
3. **ESP 不用 imgui 窗口**，用的是 `get_foreground_draw_list()`。

## 三、编译

```powershell
# 装 32 位目标（游戏是 32 位的，必须编成 i686）
rustup target add i686-pc-windows-msvc

cargo build --release --target i686-pc-windows-msvc
```

产物：`target\i686-pc-windows-msvc\release\ac_esp.dll`（注入游戏后用任意 dll 注入器加载）。

依赖版本要对齐：`hudhook 0.9` ↔ `imgui 0.12`，升其中一个必须同时升另一个，
否则 `Ui` 类型对不上会编译报错。

## 四、注入后不显示？按这个顺序查

打开菜单最下面的「自检」区域：

| 现象 | 原因 |
| --- | --- |
| 数据状态 = 无数据 | 还在主菜单 / 换图中；或 `VIEW_MATRIX` 偏移错 |
| 原始玩家数 = 0 | `PLAYER_COUNT` 偏移错（或没进对局） |
| 有玩家数但通过校验 = 0 | **实体列表布局错** → 在自检里手动切「内联数组 / 指针数组」；两个都不行就是 `HEAD_POSITION` / `FEET_POSITION` 坐标偏移错 |
| 通过校验 > 0 但屏幕没框 | `VIEW_MATRIX` 偏移错，或「不画尸体」把敌人过滤了（把该勾去掉试试） |
| **敌人死了尸体不消失** | 生死判定范围写窄了：实测尸体血量是 **`-10`（不是 0）**。如果按 `0~100` 过滤，`-10` 会被当成“偏移错、没读到”，然后按“当成活着”处理 → 尸体就一直在。见下方「血量实测结论」 |
| 有方框但位置偏 | 用了 `GetWindowRect`（应该用 `GetClientRect`），或视图矩阵错 |
| 菜单点不中 | 勾上「菜单打开时解除光标锁定」 |

自检里那几个数字的含义，就是排查顺序：
`原始玩家数` → `列表槽位值 / 使用布局 / 数组基址` → `通过校验` → `视图矩阵首行`。
「实体样本」里的 `OK/NG` 是每个实体的原始头脚坐标，一眼能看出偏移对不对。

### 血量实测结论（这个问题已经解决）

用自检面板实测出来的值（AssaultCube 1.2.0.2）：

| 状态 | `entity + 0xEC` 读到的值 |
| --- | --- |
| 活着 | `100` |
| 尸体（还没复活） | **`-10`** ← 不是 0！ |

所以尸体在实体列表里会留到本人复活，但**血量确实变了**，可以直接用来判断生死。
坑就在「合理性范围」上：

* 一开始按 `0~100` 过滤 → `-10` 被当成垃圾值丢掉 → 又按“读不到就当活着”处理 → **尸体滤不掉**；
* 现在放宽到 `-100~200`（`data.rs::health_is_plausible`）→ `-10` 被正确识别为“死亡”，
  同时 1065353216 这种真正的垃圾值仍然会被挡掉。

一句话：**能用来判断数据对错的“合理范围”，比看起来要宽**。定得太紧，
你会把真实数据当垃圾扔掉；定得太松，你会把垃圾数据当真。这个平衡只能靠实测。

### `STATE` 偏移现在是备用的

原来打算用 `state == 0`（0 活着 / 1 死亡）来筛尸体，实测发现血量已经够用，
所以 `offset.rs::STATE` 保持 `None` 就行 —— 不需要再扫了。
换游戏版本时如果发现血量不灵了，再用下面的字段扫描把那时的 `state` 找出来。

### 偏移不要靠猜：字段扫描（菜单最下面那个）

血量、状态这两个偏移都不要靠猜，直接对比出来：

1. 活人和尸体同时在场（或者站到敌人旁边）；
2. 点「扫描实体字段」——它会把实体前 `0x400` 字节里每个 int 字段都读出来排成表；
3. 把敌人打死，再点一次；**哪一行的数字变了，那个偏移就是要找的字段**；
4. 懒得对比两次也行：勾上「只看小整数（0~8）」，「可疑字段」那行会直接把候选列出来，
   其中一个是 `0`、另一个是 `1` 的基本就是 `STATE`；
5. 把结果填进 `offset.rs`（`STATE` / `HEALTH`），然后菜单里的滑块改回 `0`。

两个勾的含义：
* 「只看不同的行」——各实体取值相同的行没信息量，滤掉；
* 「只看小整数（0~8）」——状态码、队伍号这类字段都是小整数，
  而指针/浮点一读就是大数，能一下把噪声干掉。

偏移都是 AssaultCube 1.2.0.2 的值，换版本要用 Cheat Engine 重扫。

## 五、和完整版的差别（这里是刻意简化的地方）

* 删掉了队友颜色 / 队友过滤（`TEAM` 偏移没验证，属于死代码）；
* 删掉了名字显示（`NAME` 偏移没验证，留着只会显示「?」）；
* 输入过滤只保留「智能」一种模式（另外两种模式没什么学习价值）；
* 血量判断的范围在 `data.rs::health_is_plausible`：范围卡太死会把真数据丢掉（实测坑），
  所以放宽到 `-100~200`；
* `LOCAL_PLAYER` 保留为 `None`：AC 的实体列表里**只有别人**（自检里「槽位指针」能看出来），
  所以「不画自己」用不上；
* 距离数字那套「从视图矩阵反推相机位置」的代码（约 150 行）已整体删除：
  实测偏差不好控制，而它只服务于距离数字。真想做的话看第「六」节的功能清单。

保留下来但比原版更简短的：**实体列表布局自动检测**（`data.rs::choose_layout`）。
原版有几百行注释和诊断，这里压到几十行，但逻辑一样：
抽样给两种布局打分，谁像玩家用谁，并缓存结果避免每帧横跳。

✅ = 已实现，⬜ = 故意没做（附上“想做该从哪下手”）。

| 功能 | 状态 | 位置 / 想做的思路 |
| --- | --- | --- |
| 方框 | ✅ | `esp.rs` |

| 血条（随血量变色） | ✅ | `esp.rs::health_color` |

| 菜单（所有开关可改） | ✅ | `menu.rs` |
| 热键（Insert / F2 / F7）+ 吞键 | ✅ | `hotkeys.rs` |
| 中文界面 | ✅ | `fonts.rs` |
| 鼠标穿透（菜单开着也能打枪） | ✅ | `lib.rs::message_filter` |
| 自检面板（排查偏移） | ✅ | `menu.rs` 自检区 |
| 实体列表布局自动检测 | ✅ | `data.rs::choose_layout` |
| 字段扫描（自己找偏移） | ✅ | `data.rs::scan_fields` + `menu.rs` |
| 队友颜色 / 队友过滤 | ⬜ | 需要 `TEAM` 偏移：用字段扫描找“小整数且稳定”的那个 |
| 名字显示 | ⬜ | 需要 `NAME` 偏移：扫描表里那种一读就是 `0x...` 指针、指向可读字符串的字段 |
| 距离数字 | ⬜ | 要反推相机位置。思路：视图矩阵第 4 列就是平移，`eye = -Rᵀ·t`；
重点是要量到对方的**头**而不是脚（不然白多一个身高） |
| 不画自己 | ⬜ | 需要 `LOCAL_PLAYER` 偏移；但 AC 列表里本来就没有你自己 |
| 自瞄（FOV 选目标 + 平滑） | ✅ | `aimbot.rs`：和 ESP 共用同一套投影，把「画框」换成 `SendInput` 相对移鼠标（`SetCursorPos` 对锁光标的 FPS 无效）；自动扳机 ⬜ 没做 |

## 七、如果你想自己从零写一遍：按这个顺序

原则：**每一步都要能编译、能验证**。别一口气写完 9 个文件再编译，
也不要一开始就写菜单 —— 先让 dll 能挂上、能读出数据、能画出一个框。

### 第 0 步：地基（目标：钩子能挂上）

1. `Cargo.toml`：`crate-type = ["cdylib"]`，依赖 `hudhook 0.9` + `imgui 0.12` + `windows-sys`。
   **这两个版本号必须配对**（hudhook 内部就用 imgui 0.12），别自己升其中一个。
2. `lib.rs`：只写 `DllMain` + `run()` + 一个空的 `render()`。
   先在里面画一句固定文字：`add_text([50.0, 50.0], 白, "hook ok")`。

> ★ 里程碑：注入后屏幕上能看到 `hook ok`。看不到就别往下走，
> 先解决注入 / 挂钩问题（这一步占比最多，但代码最少）。

### 第 1 步：`offset.rs`（先把常量表写上）

没逻辑，纯常量。不确定的（比如 `LOCAL_PLAYER`）写成 `Option::None` ，
后面所有读内存的代码都靠这张表。

### 第 2 步：`memory.rs`（能安全读 + 能算屏幕坐标）

先写 `is_readable` / `read`，**再做别的** —— 读到野指针游戏会直接崩。
然后写 `world_to_screen`（世界坐标 → 屏幕像素，就是两次矩阵乘法 + 透视除法）。

> ★ 里程碑：能用固定测试数据验证一次投影（比如朝向已知时，正前方的点应该在屏幕中心）。

### 第 3 步：`data.rs`（数据线程 + 快照）

顺序：先定结构体（`Vec3` / `Player` / `Snapshot`）→ 再写扫描循环
（读人数 → 读实体列表 → 每个实体读头/脚）→ 最后丢进 `loop + sleep` 的线程，
用 `Arc<RwLock<>>` 共享。

> ★ 里程碑：**先别画框**，先把“读到了什么”显示到屏幕上（这就是自检面板的雏形）。
> 它就是后面所有调试的前提——没有它，你只能对着黑屏幕猜。

### 第 4 步：`esp.rs`（真正的绘制）

过滤 → 投影 → 算方框 → 画线 / 框 / 血条。到这里核心功能就齐了。

> ★ 里程碑：屏幕上出现方框。

### 第 5 步：`config.rs` 然后 `menu.rs`（把参数变成可调）

先 config（纯数据、无逻辑，写起来最快），再 menu（把 config 摆到界面上）。
顺序不能反：菜单只是 config 的“遥控器”。

### 第 6 步：`hotkeys.rs` 然后 `fonts.rs`（体验层，可最后做）

热键涉及“吞键”（要包一层窗口过程），和 hudhook 关系不大；
中文字体也是独立的小事。两个都可以先不做，用菜单手动开关。

### 一句话总结

```text
Cargo.toml → lib.rs(空壳) → offset.rs → memory.rs → data.rs
           → esp.rs → config.rs → menu.rs → hotkeys.rs → fonts.rs
```

也就是跟上面「一、从哪个文件开始读」那张表一样的顺序 ——
**写和读都顺着数据流走：位置 → 读取 → 加工 → 绘制 → 操作**。

每步都编译一次：

```powershell
cargo build --release --target i686-pc-windows-msvc
```

⚠️ 注入前先关游戏（dll 被占用时编译会报「拒绝访问」）。
